# 習熟度の設計

単語ごとの習熟段階（未学習／要復習／学習中／覚えた）をどう決め、アプリの各機能とどう繋がっているかをまとめる。

学習意欲に直結する数字なので、次の2点を設計上の原則としている。

1. **直近の正誤で反転させない。** 「間隔をあけても思い出せたか」で判定する。1回正解しただけで「覚えた」にすると、翌日には忘れている単語まで覚えた扱いになり、習熟度の数字が学習の実態と乖離して意味を失う。
2. **段階そのものは保存しない。** 間隔反復の進み具合（`reviewBox`）から毎回導出する。段階を別カラムに持つと「箱は進んでいるのに要復習のまま」といった食い違いが起きうるため、判断の根拠を1つに集約している。

---

## 1. データモデル

習熟度の判定に使うのは `UserProgress`（Read-Write。マスタ更新を跨いで必ず保持される）の3つの値だけ。

| フィールド | 意味 |
| --- | --- |
| `attemptCount` | 出題された累計回数。0なら未学習 |
| `reviewBox` | Leitnerボックスの段階（0〜5）。正解で+1、不正解で0 |
| `nextReviewAt` | 次に出題すべき日時。`nil` は「未出題＝いつでも出題可」 |

`correctCount` / `lastReviewedAt` も持つが、これらは正答率の表示用で段階判定には使わない。

**復習間隔テーブル**（`UserProgress.reviewIntervalDays`）

| box | 0 | 1 | 2 | **3** | 4 | 5 |
| --- | --- | --- | --- | --- | --- | --- |
| 次回までの日数 | 0（当日） | 1 | 3 | **7** | 14 | 30 |

`masteredBox = 3`。**間隔7日**、つまり「1週間あけても思い出せた」ことを「覚えた」の条件にしている。SM-2のような可変難易度は持たせず、動作が予測できる固定テーブルにしている。

次回復習日は**日単位**で計算する（`startOfDay` に日数を加算）。朝に解いても夜に解いても、同じ日に期限が来る。

## 2. 4段階の判定ロジック

`UserProgress.status(at:)` は上から順に評価する。**順序が意味を持つ**（期限切れの判定が箱の判定より先）。

```swift
func status(at date: Date = .now) -> LearningStatus {
    guard attemptCount > 0 else { return .notStudied }   // ① 未学習
    if isDue(at: date) { return .needsReview }           // ② 要復習
    return reviewBox >= Self.masteredBox ? .memorized    // ④ 覚えた
                                         : .learning     // ③ 学習中
}
```

| 段階 | 条件 | ユーザーへの説明文 |
| --- | --- | --- |
| **未学習** | `attemptCount == 0` | まだ一度も出題されていない |
| **要復習** | 復習期限が来ている（`nextReviewAt <= now`、または `nil`） | 直近で間違えたか、復習の期限が来ている。優先して出題される |
| **学習中** | 期限前 かつ `reviewBox` が 1〜2 | 正解を重ねている途中（1〜3日間隔で再出題） |
| **覚えた** | 期限前 かつ `reviewBox` が 3以上 | 1週間以上あけても正解できた |

> **重要な帰結：「覚えた」は永続しない。**
> box3以上の単語でも、7日／14日／30日の期限が来た瞬間に**要復習へ戻る**。ホームの「覚えた」語数は放置すると減る。これは仕様で、忘却を織り込まずに数字だけ増え続ける表示は学習の役に立たないという判断による。学習履歴の習熟度の折れ線が下がることがあるのも同じ理由。

## 3. 段階の遷移

### 3.1 解答による遷移（`record(isCorrect:)`）

```
正解 → reviewBox = min(reviewBox + 1, 5)、nextReviewAt = 今日 + 間隔[新box]
不正解 → reviewBox = 0、             nextReviewAt = 今日（＝その日のうちに再出題）
どちらも → attemptCount += 1、lastReviewedAt = 現在時刻
```

**未学習から「覚えた」までの最短経路（正解3回）**

| 回 | 解答前のbox | 結果 | 解答後のbox | 次回期限 | 解答直後の段階 |
| --- | --- | --- | --- | --- | --- |
| 1 | 0 | 正解 | 1 | 翌日 | 学習中 |
| 2 | 1 | 正解 | 2 | +3日 | 学習中 |
| 3 | 2 | 正解 | 3 | +7日 | **覚えた** |
| 4 | 3 | 正解 | 4 | +14日 | 覚えた |
| 5 | 4 | 正解 | 5 | +30日 | 覚えた |

**不正解時**

| 解答前 | 結果 | 解答後のbox | 次回期限 | 段階 |
| --- | --- | --- | --- | --- |
| box 5（覚えた） | 不正解 | **0** | 当日 | **要復習** |

不正解は段階を1つ下げるのではなく**box 0まで一気に戻す**。「1週間あけて思い出せる」という主張が崩れた以上、途中段階から再開させる根拠がないため。

### 3.2 時間経過による遷移（解答なし）

期限を過ぎるだけで **学習中／覚えた → 要復習** に移る。box自体は下がらないので、期限後に正解すれば次はさらに長い間隔（例: box3→box4 で14日）に進む。

```
box3・期限7日後  →（放置）→ 要復習  →（正解）→ box4・期限14日後・覚えた
                                    →（不正解）→ box0・当日・要復習
```

### 3.3 手動での上書き（単語詳細画面）

自動判定だけでは「もう知っている語が毎回出てくる」「自信がないのに覚えた扱い」に対処できないため、逃げ道を用意している。

| 操作 | 処理 | 結果 |
| --- | --- | --- |
| **要復習にする** (`markForReview`) | `reviewBox = 0`、期限を当日に | すぐ出題対象へ |
| **覚えたことにする** (`markAsMemorized`) | `reviewBox = max(box, 3)`、期限を+7日以降に | 1週間出題されなくなる |

いずれも `attemptCount` が0なら1にする（未学習のまま段階だけ動くのを防ぐ）。

## 4. 他機能とのリンク

習熟度は表示用の指標ではなく、**出題順そのものを決めている**。

```
                         ┌──────────────────────────────┐
   4択クイズ ─┐          │ UserProgress                 │          ┌─ ホーム（習熟度バー／復習件数）
              ├─採点──▶ │  reviewBox / nextReviewAt     │ ─導出──▶ ├─ 単語帳（ステータス絞り込み・アイコン）
   タイピング ┘          │  attemptCount / correctCount  │          ├─ 聞き流し（ステータス絞り込み）
                         └──────────────┬───────────────┘          └─ クイズ結果（新たに覚えた語）
                                        │
                                   出題順を決定
                                        ▼
                              StudyQueue（優先度付け）
```

### 4.1 書き込み側：段階を動かすのは2機能だけ

| 機能 | 記録の単位 | 正誤の判定 |
| --- | --- | --- |
| **4択クイズ** | 1問ごと | 選択が正解か。**時間切れも不正解として記録**する |
| **タイピング** | 1単語を打ち切ったとき | その単語で1度もミスしなければ正解。ミスが1文字でもあれば不正解<br>（時間切れで打ちかけの単語は記録しない） |

どちらも `ProgressRepository.recordAnswer(wordId:isCorrect:)` を通り、`UserProgress` と当日の `StudyLog` を同時に更新する。**聞き流しは段階を一切変更しない**（聞いただけで覚えた判定にはしない）。

### 4.2 出題順（`StudyQueue`）

**`prioritize` — 4択クイズ（通常）とタイピングが使用**

1. 復習期限が来ている語（間違えた語・間隔が満了した語）… シャッフル
2. まだ一度も解いていない語 … シャッフル
3. まだ期限前の語 … **期限が近い順**

同じ優先度内はシャッフルするが、期限前の語だけは並びに意味があるので保つ。

**`dueWords` — ホームの「復習する単語が◯語あります」から始まるクイズが使用**

期限が来ている語**だけ**を返す。未学習語は「復習」ではないので含めない。→ **リンクの文言と出題内容が一致する。**

**`dueCount` — ホームの復習件数の表示**

`dueWords` と同じ条件で数えているので、「◯語あります」と実際に出題される語数は必ず一致する。

### 4.3 読み取り側：段階を表示・絞り込みに使う画面

| 画面 | 使い方 | 経路 |
| --- | --- | --- |
| **ホーム／習熟度カード** | 4段階の内訳バー＋語数、累計正答率 | `ProgressRepository.summarize()`（全件を1回走査） |
| **ホーム／復習リンク** | 「復習する単語が◯語あります」→ タップで復習限定クイズ | `StudyQueue.dueCount` → `TabRouter.startQuiz(scope: .reviewOnly)` |
| **単語帳** | すべて／未学習／要復習／学習中／覚えた で絞り込み、行末にアイコン | `WordFilter.apply(to:progress:)` |
| **聞き流し** | 単語帳と**同じ** `WordFilter` で絞り込み（「要復習だけ流す」が主用途） | 同上（共通化してあるので軸がずれない） |
| **単語詳細** | 現在の段階の表示と手動上書き | `markForReview` / `markAsMemorized` |
| **クイズ結果** | 「◯語が『覚えた』に到達しました」 | 1問ごとに記録の**前後**で段階を比較してカウント |
| **学習履歴／習熟度の折れ線** | 日ごとの「覚えた」語数の推移 | `StudyLog.masteredWordCount`（後述） |

### 4.4 学習履歴に残す仕組み

習熟度は `UserProgress` の**現在の状態**しか持たないため、後から遡って「3か月前は何語覚えていたか」を再計算できない。そこで解答を記録するたびに、その時点の「覚えた」語数を当日の `StudyLog.masteredWordCount` に**スナップショットとして焼き付けている**。

グラフ描画時（`StudyHistory.series`）の扱い：

- **学習しなかった日は0にせず、直前の値を持ち越す。** 休んだ日に覚えた単語が消えたように見えるのを防ぐ。
- **期間より前の記録からも開始値を引き継ぐ。** 引き継がないと、期間内に学習日がないだけで折れ線が0から始まってしまう。
- 週次集約（3か月以上の期間）では、解答数は**合計**、習熟度は残高なので合計せず**その週の最終値**を採る。

## 5. 設計上の判断と既知の制約

**判断**

- **段階を保存せず導出する。** 判断根拠が `reviewBox` 1つに集約され、食い違いが起きない。代わりに `status` の評価には現在時刻が必要なので、テスト可能なように `status(at:)` で時刻を注入できる形にしている。
- **不正解はbox 0まで戻す。** 段階的に下げるより挙動が予測しやすく、「間違えた語はその日のうちにもう一度出る」という分かりやすい約束になる。
- **「覚えた」を7日間隔に置いた。** 3日（box2）だと直前の記憶で正解できてしまい、14日（box4）だと到達に日数がかかりすぎて達成感が得られない。
- **時間切れを不正解として記録する（クイズ）。** ただし結果画面では「選択ミス」と「時間切れ」を分けて表示する。対策が「覚え直す」か「速く解く」かで変わるため。

**既知の制約**

- **同日に連続してクイズを回すと、間隔を待たずにbox3へ到達できる。** 出題プールは期限前の語も末尾に含むため、セットを繰り返せば同じ語が再び出る。「1週間あけて思い出せた」という定義からは外れるが、意図的に繰り返した場合に限られ、かつ7日後の期限が来れば要復習に戻って再検証されるので、実害は限定的と判断して許容している。
- **`summarize()` は `UserProgress` 全行を materialize する。** SwiftDataに集計クエリが無いため。語彙数が数千規模で体感できるほど遅くなったら、集計値を別モデルに持たせて解答時に加算する方式へ切り替える。
- **タイピングは単語単位でしか記録しない。** 1文字ミスでも不正解になるため、4択クイズより厳しく段階が下がる。
